CONVENTION IN FORCE  --  a tax number without one is not a measurement
==============================================================================

  CONTEMPORANEOUS CORE, COMMITTED HISTORY ONLY.

  Commit X is RED iff, using the base and pathspec that X's OWN README
  named and only if the guard file existed in X's OWN tree,
      git diff <base>..X -- <pathspec-at-X>
  is non-empty. The cited target ref is resolved to X.

  The guard changed shape three times. Only the assertion COMMON to all
  three shapes is used for the red/green verdict, because neither shape
  change alters that verdict for an already-committed commit:
    - the full-clone/unreachable-base rule only turns a SKIP into a FAIL;
    - the working-tree comparison changes WHEN a breakage is visible, not
      whether the commit is red once it exists (at commit X, a clean
      checkout's working tree IS X's tree, so the two comparisons agree).
  The one genuine divergence -- the ambiguity rule, which fails when the
  section names more than one cited command -- is reported per commit as a
  counterfactual instead of being folded into the verdict.

  Timeline is FIRST-PARENT (the mainline as pushed). A merge counts as
  touching the pathspec when its diff vs its FIRST parent does; the
  side-branch commit it carried is not billed a second time.

RECOMMENDATION
==============================================================================

THE RITUAL IS INTRINSIC TO THE SELF-FALSIFYING CLAIM. It is NOT an artifact
of an over-claiming pathspec. Four findings force that, in order of weight:

1. THE GAP IS NEVER ZERO, AND CANNOT BE. All 6 repairs took at least one
   later commit (gaps 1, 1, 2, 1, 2, 3; 0 same-commit repairs). That is arithmetic,
   not indiscipline: the citation names a CI RUN ID, CI runs on push, and a
   push cannot precede the commit. A commit cannot cite the run that tested
   it. Narrowing the pathspec changes how OFTEN you pay; it cannot make the
   gap zero, so it cannot retire the ritual.
   Corroborating, derived: the cited base 7e50d6f does NOT itself touch the
   pathspec; the commit that actually carried the change is a302f71. The
   citation names the SHA a PUSH was tested at, not the SHA that broke it --
   which is the per-push unit showing through in the document itself.

2. EVERY BREAKAGE WAS A TRUE FALSIFICATION. 6 of 6, and the realized
   over-claim is 0: every file ever billed under the cited pathspec is a
   file CI executes or consumes. Not one of these commits was punished for a
   change that could not have moved the cited matrix. There is no component
   to indict on the evidence of what has actually happened.

3. THE ONE COMPONENT WHOSE BREADTH EXCEEDS ITS OWN PROSE IS `.github`, and it
   has cost nothing. The pathspec names the whole directory while the section
   describes the trigger as "the workflow itself"; a future
   .github/ISSUE_TEMPLATE or dependabot.yml would falsify the citation without
   moving a single CI number. That is a LATENT over-claim, and it is named
   here for honesty -- but it is not the mechanism of the measured tax,
   because the directory has only ever contained the workflow.

4. THE TAX IS DOMINATED BY THE APPARATUS, NOT THE PRODUCT. 0 of the 6 breaking
   commits touched src/ or bin/ at all; 5 were caused by a test file whose
   own subject is README.md. The citation is mostly being falsified by the
   machinery built to check the citation. That is self-reference, not
   over-claim: those tests live under test/, CI counts them, and the section
   publishes the counts, so their arrival genuinely retires the run. A guard
   that lives inside the pathspec it guards must falsify itself on arrival.

The section is not over-claiming its PATHS. If anything it under-claims its
UNIT: the assertion is per-commit while the evidence it cites is per-push.
That mismatch, not the breadth of the paths, is what makes the ledger read
like a ritual.

NO ACTION IS PROPOSED AND NONE WAS TAKEN. This item changes nothing: not the
pathspec, not the assertion, not the citation. The recommendation IS the
deliverable. If a later item wants a lever, the data points at the UNIT of
the claim, not at the breadth of the paths.
